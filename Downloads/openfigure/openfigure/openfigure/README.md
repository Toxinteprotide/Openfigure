# openfigure

Open-source scientific figure editor in the spirit of tools like BioRender: drag curated schematic icons onto a canvas, connect them with meaningful arrows (activates, inhibits, binds, translocates), recolour named parts, and export clean SVG/PNG. MIT-licensed, zero runtime dependencies, runs in the browser and in Node.

> **Status: v0.1 MVP.** The editor, scene model, renderer and 27 starter assets work and are tested. The assets are original, simplified and **not yet reviewed by a domain scientist**: check biology before publishing a figure.

## Quick start

```bash
npm run serve                     # editor at http://localhost:5173
npm test                          # 14 unit tests (Node >= 18, no install step)
node bin/openfigure.js render examples/mapk-pathway.json out/mapk.svg
```

## What is in the box

| Area | What works |
| --- | --- |
| Canvas | Drag, marquee, shift-select, resize (assets keep aspect), rotate (Shift = 15° steps), nudge, zoom, grid |
| Alignment | Snap to edges/centres of other objects and the page (Alt disables), align and distribute |
| Structure | Z-order, groups, lock, duplicate, compartment regions |
| Pathways | Connectors attach to ports and follow when nodes move; straight / elbow / curved; four biological meanings |
| Library | 27 assets in 6 domains, synonym + typo-tolerant search, recolourable parts |
| Output | SVG with real text, `<title>` and a generated `<desc>`; PNG at 1×/2×/4×; JSON documents |
| Safety | Undo/redo, autosave to localStorage, missing assets render a visible placeholder |
| Accessibility | Keyboard-operable library and inspector, visible focus, labelled controls, dark mode |

## Library API

```js
import { createDocument, createAssetNode, createConnector, library, renderSvg } from 'openfigure';

const doc = createDocument({ width: 800, height: 400, title: 'Receptor activation' });
const ligand = createAssetNode(library.get('immuno-cytokine'), { x: 80, y: 40 });
const receptor = createAssetNode(library.get('receptor-gpcr'), { x: 80, y: 220 });
doc.nodes.push(ligand, receptor,
  createConnector({ node: ligand.id, port: 'auto' }, { node: receptor.id, port: 'auto' }, { semantic: 'binds' }));
const svg = renderSvg(doc);   // string
```

The renderer is shared by the editor and exporter, so what you see is what you export. Documents are plain JSON (`schema: 1`) and are validated on load.

## Layout

```
src/core      scene model, undo store, geometry (ports, routing, snapping), SVG renderer
src/assets    asset library + search
src/editor    static browser editor (no build step)
bin           CLI: serve | render | validate
examples      MAPK pathway (generated by build-example.js)
test          node:test suite + optional Playwright smoke test
```

## Design decisions

- **Flat, z-ordered node list** instead of a deep tree: simple to diff and to serialise. Groups are a tag.
- **Connectors reference node ports**, never coordinates, so pathways stay connected during edits.
- **Snapshot undo** (structured clone, 100 steps, drags coalesced): fine at figure scale; swap for ops/CRDT when real-time collaboration arrives.
- **SVG-first**: crisp at any size, editable in Illustrator or Inkscape, and PNG is just a rasterised SVG.
